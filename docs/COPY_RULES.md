# Dokkit Copy Rules

**Voice:** Impersonal, calm, concrete. Never imply “I/we decided for you.”

| Prefer | Avoid |
|---|---|
| “Carried to Wednesday” | “Overdue”, “You missed this” |
| “About 1h 40m left” | “Productivity: 62%” |
| “Still needs doing” | “Failed”, “Incomplete — act now” |
| “Reshape the plan” | “I’ve optimised your day” |
| “Couldn’t save that. We’ll try again.” | Raw technical error such as “Mutation failed: HTTP 500” |
| “Your day is clear.” | “Nothing here yet! Get started!” |
| “Site write-ups after meetings running ~10 min longer” | “I noticed you’re slow at…” |

## Rules

- No first-person product voice, agent/copilot persona, or unsolicited advice chat.
- Interpretation and capacity reasoning may propose; copy must not imply execution before user confirmation.
- Success language is only shown after persistence is confirmed. Pending, failed, and retry states must remain understandable and recoverable.
- Carry and unfinished work are neutral states, never moral judgements.
- Insights use one evidence-shaped sentence, remain impersonal, are high-confidence, and are overridable. Avoid imperatives unless the user is already in an action.
- No streaks, scores, badges, leaderboards, confetti, productivity percentages, or “AI” badge theatre.
- Error copy should explain what happened in ordinary language and preserve the user's draft.
